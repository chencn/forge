# 保存冲突与磁盘版本校验

编辑器保存使用乐观锁：打开或上次保存时记录 `modifiedMs`，写入时把它作为 `expectModifiedMs` 交给后端。后端在取得全局文件写锁后重新读取磁盘修改时间；时间不一致就返回 `CONFLICT_ON_WRITE`，不会覆盖外部工具、其他编辑器或 Git 刚写入的版本。

## 冲突处理

前端保存冲突时保留三份文本：

- `base`：上次与磁盘一致的基线；
- `ours`：编辑器当前未保存文本；
- `theirs`：冲突对话框打开后重新读取的磁盘文本。

用户可以接受磁盘版本，也可以在三向合并结果中继续编辑。合并结果保存时仍以对话框实际读到的 `theirs.modifiedMs` 做第二次乐观锁校验。若对话框打开后磁盘再次变化，后端再次拒写；新的冲突以“刚整理出的合并结果”为 `ours`、以上一次看过的磁盘正文为 `base`，因此不会丢掉用户已经完成的合并工作。

## 退出握手

开启退出保存时，后端拦截关闭并发送 `app://flush`，同时启动五秒看门狗。前端串行保存全部脏文档：

- 全部保存成功后调用 `app_exit`；
- 任一文档因冲突或错误仍为脏状态时调用 `app_cancel_exit`，窗口继续保留供用户处理。

看门狗带退出轮次编号。取消后再发起的新一轮退出不会被旧看门狗误结束；只有前端页面崩溃、完全无法回复且轮次仍有效时，后端才在超时后强制退出。

## 写入串行化

普通保存和本地历史恢复都通过 `fs_write_lock()` 后调用同一套原子写入实现，避免两个入口同时争用固定临时文件或相互覆盖。读取与目录扫描不占该锁。

## 代码位置

- `src-tauri/src/fs/mod.rs`：乐观锁、全局写锁与原子写入。
- `src/hooks/useDocuments.ts`：保存现场、冲突状态、二次版本校验与脏状态判定。
- `src/components/MergeConflictDialog.tsx`：读取磁盘版本并提交合并结果。
- `src-tauri/src/tray.rs`、`src/lib/window.ts`、`src/App.tsx`：退出保存、取消与看门狗握手。
