# 三向合并与本地历史

## 三向合并

保存检测到磁盘版本变化后，界面显示本地文本、磁盘文本和可编辑结果。共同祖先是文档上次与磁盘一致的 `baseline`。Monaco standalone 没有公开的 merge editor，因此界面由两份只读编辑器和一份可编辑结果组成。

行级合并器先分别计算 `base → ours` 与 `base → theirs` 的编辑区间，再按区间关系合并：

- 只有一侧修改的区间直接采用该侧；
- 两侧得到相同文本时直接采用一份；
- 相邻但不重叠的修改分别应用，例如本地改第一行、磁盘改第二行会自动得到两项修改；
- 同位置插入、严格重叠修改，或插入落在另一修改区间内部时进入冲突块；
- 插入位于另一修改区间边界时可独立应用。

冲突块可整体选择本地、磁盘或两边都保留，也可直接编辑带标记的默认结果。最终写入仍执行磁盘版本校验，细节见 [保存冲突与磁盘版本校验](../workspace-watch/save-conflicts.md)。

## 本地历史

打开文本时先记录原版，保存前后、冲突合并成功、外部变化及删除前继续记录正文、行尾、BOM、编码和事件。自动快照限制在 2 MiB 内；恢复前保护未保存文本不受此限制。历史保存在应用配置目录的 `local-history/` 下，每个文件最多保留 50 条，正文和写盘元数据均相同时去重。写入通过历史锁串行化，并使用原子替换防止截断历史。

工作区目录和文件相对路径使用固定算法的 FNV-1a 64 位哈希。文件路径哈希包含完整相对路径和目录分隔符，因此 `a_b/c.txt` 与 `a/b_c.txt` 不会落入同一份历史；固定长度文件名也避免 Windows 长路径问题。这里不使用 Rust 的 `DefaultHasher`，防止工具链变化后持久化目录名改变。

本地历史在编辑器页签中显示，左侧 260px 时间线，右侧复用完整差异编辑器。文件、目录及已删除文件使用同一查询；Ctrl/Cmd 多选或 Shift 连选同一文件的修订可比较最旧与最新版本。放置标签会保存作用域内的磁盘版本与已打开编辑器缓冲区，不把未保存文本写进工作区；恢复标签仅作用于标签与当前历史页范围的交集。

恢复前显示文件范围并确认，先保护未保存文本，再在普通保存共用的文件写锁内保护当前磁盘版本。写回使用比较时的磁盘版本做乐观校验，保留原行尾、BOM 与编码，已删除文件会重建父目录。返回的磁盘正文和修改时间同步编辑器、目录树与 Git 状态，历史页签继续保留。读取或恢复失败明确显示，不再把错误当成空历史。

## 代码位置

- `src/lib/merge.ts`、`tests/lib/merge.test.ts`：三向合并算法及回归测试。
- `src/components/MergeConflictDialog.tsx`：冲突界面。
- `src/hooks/useDocuments.ts`：冲突状态和历史记录触发点。
- `src/components/LocalHistoryEditor.tsx`、`src/lib/localHistory.ts`：历史时间线、标签、比较和恢复。
- `src-tauri/src/local_history.rs`：快照索引、轮转、读取和恢复。
