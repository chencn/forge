# Git 日志工具窗口

对应 IDEA 的 Log 工具窗口。三栏：左引用树，中提交列表，右本次提交的文件清单与详情。引用树左边一条竖向动作条。

主体在 `src/components/GitLogPane.tsx`，命令契约见 `../../backend/`。引用树的右键菜单与 `../git-branches/`
共用一份 `src/lib/refMenu.ts`，第三栏文件树的分组规则与 `../git-commit/` 一致。

## 布局

- 三栏可拖，默认权重 `refs 2 / list 4 / detail 3`。
- 拖某条分隔条只重分它左右两栏，第三栏不参与换算。基准是这两栏的像素宽度之和。
- 两栏合计不足 40px 时该次拖动不响应；单栏权重限制在 0.6 到 `两栏之和 - 0.6` 之间。
- 底部 dock 时高度强制不低于 380px。三栏并排，低于这个高度不可读。
- 引用面板整块可收起，收起后只剩竖向动作条贴在左边，`refs` 与 `list` 之间的分隔条同时不画。收起用 `hidden`
  属性，CSS 里 `.log-refs[hidden] { display: none }` 覆盖默认的 `display: flex`。

## 左列：引用树

- 四层结构：`HEAD(当前分支)` / `本地` / `远程` / `标签`。`HEAD` 那行的 `value` 是空串，空串在 `git_log`
  里等于不写引用，即当前分支。
- 组名不放计数（`groupHead`）。IDEA 的引用树同样没有，这一列也没有按条数排序的动作。
- 计数只在第三栏的目录行与模块行右侧，文案 `N 个文件`，字色 `--text-muted`，`showDetails` 开着才画。
- 空组整组不列，按 `section.count > 0` 过滤。标签一组的计数在「显示标签」关掉时算 0。
- 远程先按远端分一层，层里的叶子只显示远端名后面那截，`value` 仍是全名（`remoteLeaf` / `remoteNode`）。
- 本地分支按斜杠嵌成目录，看齿轮里「按目录分组」那一档（`buildRefTree` / `renderLeaves`）；关掉是平铺一条。
- 徽标两类：当前分支挂 `Tag` 字形，远端默认分支挂 `Star`，都是 12px、`--accent-yellow` + `fill: currentColor`。
- 远端默认分支由 `refs/remotes/<远端>/HEAD` 的符号引用指出，它本身不进分支列表。用 `%(refname:short)`
  会被 git 折成 `origin`，凭空多出一条不存在的分支。
- 收藏也画 `Star`（`leafBadge`），字形和颜色与远端默认分支的徽标相同，两者同时命中时并排显示两个 `Star`。默认分支的徽标
  只出现在远程一节的叶子上，收藏徽标在本地和远程两节都会出现。标签行不带收藏徽标。
- 同层排序权重：当前分支 0 / 收藏的 1 / 含收藏的目录 2 / 其它目录 3 / 其余 4，同权重按名字比较
  （`leafWeight`、`renderRefNodes`）。
- 三个分组按是否含收藏排：有收藏的那一组排到前面，其余保持本地 / 远程 / 标签次序。
- 收藏名单存在 `settings.branches.favorites`，按列表里的名字存，与顶栏分支弹层同一份。
- 单击行为由齿轮里「单击时 仅选中 / 筛选这条分支」决定，默认「仅选中」：一次筛选要重跑 `git log`。双击总是筛到这条。
- 折叠全部连每个远端那一层和每层目录一起收，键的算法与渲染一致（`everyGroupKey`，键形如 `remote/<远端>`、
  `refdir/<路径>`）。
- 齿轮三项：单击时（两档）、按目录分组、显示标签。

## 左列的竖工具条

按钮自上而下：收起 / 显示引用面板、新建分支、更新、删除、与当前比较、抓取、收藏、日志定位、齿轮、展开全部、折叠全部。

门控条件：

- 新建分支、日志定位：要求选中过一条引用（点过或右键过）。
- 更新：额外要求该引用有上游；没有上游时悬停提示换成 `git.noUpstream`。
- 删除、「与当前比较」：在当前分支那行不可点。删除按钮对标签时提示文字用 `git.refDelete`，其余用 `git.deleteSelected`。
- 抓取：没有配远端、或正在抓取时不可点，期间按钮自己转，提示换成 `git.fetching`。
- 收藏：对标签不可点。标签收藏不了。
- 引用面板收起后，除收起 / 显示那个按钮外其余按钮都不画。

## 中列：筛选

- 四个筛选条件：文本框、作者下拉、日期下拉、引用。引用不在筛选条上起手，由左列的点选或引用菜单里的「与当前比较」
  写入，在筛选条上以一个可关闭的 chip 显示。第五个 chip 是路径，由右列「迄今为止的历史记录」写入。
- 文本框落定 250ms 再查，其余筛选是选出来的，不等。
- 文本框右侧的 `Regex` 图标切换 `--extended-regexp` 与 `--fixed-strings`。
- `--grep` 和 `--author` 同时给时后端补 `--all-match` 取交集，git 默认是并集。
- 作者候选取最近 500 条提交里出现过的人，按各人最近一次出现排。取失败时下拉只剩「不限」。
- 日期三档：24 小时 / 7 天 / 一个月，算成 `--since=@<unix>`。
- 列表上限 200 条，Rust 侧 clamp 1..500。
- 引用可写 `a..b` 比较两段，两段各自过 `valid_branch_name` 校验。
- 路径过滤放在 `--` 之后，否则带斜杠的名字会被 git 当成引用。
- 查询失败清空列表和选中集。留着上一次的结果会被读成过滤生效。
- 筛选条尾部是刷新按钮，`logLoading` 时转。只在有筛选条件时多出清除全部按钮，清掉文本 / 作者 / 引用 / 日期 /
  路径五项，不动正则那一档。

## 中列：多选与提交行菜单

- 单击只留一条；`Ctrl` / `Cmd` 加选或取消；`Shift` 按列表可见顺序，从最后一个已选的行连选（`pickCommit`）。
- 选中集按点击先后存，详情栏跟最后选中的那条走。
- 提交行右键菜单次序照 IDEA 的 `Vcs.Log.ContextMenu`，门控如下（`commitMenu`）：

| 项 | 键位 | 要求 |
| --- | --- | --- |
| 复制修订号 | `Ctrl+Alt+Shift+C` | 多选时把选中几条的完整哈希一次复制，换行分隔 |
| 创建补丁 | | 右键落在哪条就出哪条的补丁，多选不影响它 |
| 优选 | | 恰好一条，且不是合并提交 |
| 签出（子菜单） | | 恰好一条；子菜单挨个列本地分支（当前那条不算），末尾挂「签出修订」；没有别的本地分支时只落「签出修订」一条 |
| 比较版本 | | 恰好两条才出现，不是置灰 |
| 与本地比较 | | 恰好一条 |
| 将当前分支重置到此处（软 / 混合 / 硬） | | 恰好一条；硬档先弹一句确认 |
| 还原提交 | | 恰好一条，且不是合并提交 |
| 撤销提交 | | 只在 HEAD 那条上 |
| 编辑提交消息 | | 只在 HEAD 那条上 |
| 推送此前所有提交 | | 恰好一条，且当前分支不游离、仓库配了远端 |
| 新建分支 / 新建标签 | `Ctrl+Alt+N`（仅新建分支） | 恰好一条 |
| 转到子提交 / 转到父提交 | `LEFT` / `RIGHT` | 目标出现在眼前这份列表里才可用 |

- 合并提交让优选和还原置灰：要先定并入哪一条父提交，提示 `log.needSingleParent`。
- 撤销提交落 `git reset --mixed HEAD^`：HEAD 退一格，改动留在工作区且不暂存。这一项只在 HEAD 上可用，所以直接写
  `HEAD^`；根提交没有父，git 自己报错回界面。
- 编辑提交消息不起新命令：叫出提交面板并勾上修正，改完按提交就是 amend。
- 推送此前所有提交落 `push <远端> <修订>:refs/heads/<分支>`，不加 `--force`，远端已经走得更远时 git 自己拒。
- 转到父 / 子：父和子都只在这份可见列表里才算。多个候选起一层子菜单，一个都没有时整项不可用并给一句
  `log.noNeighbour`，不留下空箭头。
- 菜单上画了的键位全部由窗口级 `keydown` 接住，输入框和编辑器里的按键一律让行。方向键只在恰好选中一条、
  且这一侧有可跳的行时才拦下按键。
- 右键落在没选中的行上时，选中集先换成它自己。这一次判定读就地算出来的那份，不读 state：`setPicked` 要下一次渲染
  才生效，读 `picked` 会让判定停在旧选择集上。

## 右列：文件树与预览

- 上半是文件树，下半是提交详情。详情整条可收起，收起只剩「提交详细信息」一行标题。
- 详情字段：哈希 / 作者 / 作者时间 / 提交者 / 提交时间 / 父提交。作者时间与提交时间分开列，变基或代提交时两者不是
  同一个人。
- 文件树分组规则与提交窗口一致：仓库根节点一行、目录逐层、文件行带状态字母；`showDetails` 开着时行末带 `+N −M`。
- 目录默认展开（`closedFileDirs` 是收起集，初值为空），与提交窗口相反。这边一次只看一次提交，收起没有意义。
- 树上方那条栏：左边折叠全部 / 展开全部，两者的 disabled 条件互反，没文件时不能折、没收起时不能展。比对模式起来后
  中间多出一个可关闭的 chip。右边的眼睛分裂按钮开视图弹层：分组依据 目录 `Ctrl+Alt+P` / 模块 `Ctrl+Alt+M`，
  布局 显示详细信息 / 显示差异预览。
- 数据源两份：默认列选中那次提交改到的文件；`compareRef` 起来后改成列那条引用对工作区的改动
  （`git diff --name-status -z <rev>`）。
- 比对模式下这一栏的行不响应单击，双击是引用与工作树的比对，右键只剩「显示差异 / 编辑源」两项。
- 选中提交时点亮它改的第一个文件，点开标签要双击：一次单击不新增标签页。
- 预览开着时树下面压一块只读的 diff 文本，取的是 `parents[0] → 这条提交`。根提交用空树哈希 `4b825dc…` 当左侧。
- 双击文件把比对开到编辑区标签页，两侧取自仓库：`<rev>^:<路径>` 与 `<rev>:<路径>`（`git_commit_file`）。
  「在新标签页中显示差异」靠一个自增后缀另开一个标签，否则同一处比对复用同一个标签。

## 文件行的十四项右键

次序照 IDEA：显示差异 `Ctrl+D` / 在新标签页中显示差异 / 与本地比较 / 将之前版本与本地版本进行比较 / 编辑源 `F12` /
打开仓库版本 / 分隔线 / 还原所选更改 / 优选所选更改 / 将所选更改提取到单独的提交 / 删除所选更改 / 创建补丁 /
从修订中获取 / 迄今为止的历史记录 / 显示对父项的更改。

- 优选、提取到单独提交、删除所选三项永久置灰。它们对应提交窗口那一侧对着工作区才执行的动作，日志里对着一次提交
  没有落点，照 IDEA 保留但不可点。缺口见 `../../plans/change-selection-actions/`。
- 根提交那行的「将之前版本与本地比较 / 还原所选更改 / 显示对父项的更改」同样不可点，条件是 `hasParent`。
- 还原所选更改把父提交的那份写回工作区（`restore --source <父> --worktree -- <路径>`），等于撤销那次改动。
- 从修订中获取把这条提交的那份写回工作区。
- 打开仓库版本开的是只读虚拟文档，不在磁盘上，键是 `路径@短哈希`。二进制文件开不出文本，同一个键下落的是
  一条打不开的告示。
- 迄今为止的历史记录不进 App，只把中列的 `path` 收窄到这个文件，筛选条上出一个可关闭的 chip。IDEA 那边换一个
  只列这个文件的历史标签，这里同一份中列加个过滤就够。
- 比较版本开的是这两段之间的差异文本一页（`git diff --no-color --no-ext-diff <左> <右>`）。IDEA 先列改动清单再选
  文件，这里直接落到编辑区标签。
