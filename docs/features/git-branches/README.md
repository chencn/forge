# 分支弹层与引用动作

主工具栏分支芯片点开的弹层，加上一套「任何一条引用右键」的动作。菜单本体只有一份 `src/lib/refMenu.ts`，
顶栏弹层和日志左边的引用树共用。逐条适用矩阵见 [`ref-action-matrix.md`](./ref-action-matrix.md)，
日志那一侧的树见 `../git-log/`。

## 芯片

- 画 `GitBranch` 字形 + 当前分支名 + 同步状态 + 下箭头。芯片最大宽度 260px，分支名超长时截断加省略号。
- 同步状态是叠起来的两个 8px 箭头，中间留 1px，不写数字：进来的蓝（落后）在上，要推的绿（领先）在下，
  颜色取 `--accent-blue` 与 `--accent-green`。条数只在悬停提示里，提示同时带仓库根路径。
- 没有仓库时芯片不是灰的 `—`，改成 IDEA 那颗「版本控制 ▾」，菜单给「创建 Git 仓库…」（`git_init`，
  只建 `.git`，不动任何文件）。IDEA 那张菜单里还有「共享到平台」「其他 VCS」「本地历史记录」三条，
  forge 三样能力都没有，就不摆点了没反应的死控件。连文件夹都没开时这一颗压根不画——「打开文件夹」
  工程芯片那里已经有一条，不在这里摆第二个入口。

## 弹层头部

- 搜索框右边跟两个按钮：抓取、齿轮。弹层最小宽度 320px。
- 抓取在一个远端都没配时不可点，对应 IDEA 的 `hasRemotes`。跑起来时按钮自己转，提示换成「抓取中…」，期间仍不可点。
- 齿轮里三条显示开关：搜索结果里加入操作、显示最近分支、显示标签，存在 `settings.branches`。

## 动作两排与搜索

- 第一排 更新项目 / 提交 / 推送 / 抓取远端，第二排 新建分支 / 新建标签 / 签出标记或修订，两排之间一条分隔线。
- 搜索串同时匹配界面文案和一份英文别名：`update project pull merge`、`commit`、`push`、`fetch`、
  `branch new`、`tag new`、`checkout revision tag`。搜的多半是英文命令名，只匹配中文文案等于搜不到。
- 「在搜索结果中加入操作」只管搜索那一档。没在搜时动作照常列，照 IDEA。

## 四个分节

- 最近 / 本地 / 远程 / 标签，每节一个可点的节头。
- 默认只展开「最近」，`closedSections` 初值是 `local` / `remote` / `tag`。
- 一旦开始搜索，四节都展开（`sectionOpen`）。命中的行藏在收起的那节里就等于搜不到。
- 远程那一节里再按远端名分一层，各层自己可收，状态按远端名记（`openRemotes`）。
- 空节不画。

## 收藏

- 每行左边的图标是收藏开关：点图标本身翻收藏，点文字是签出，对应 IDEA 的 `handleIconClick`。
  收藏的行图标从 `GitBranch` 换成实心 `Star`。
- 收藏的那几条在同组里排到前面，其余次序不动。
- 「最近」那一节不重复列收藏过的和当前分支。
- 名单按列表里的名字存：本地不带 `refs/heads/` 前缀，远端带 `origin/`。日志的引用树和顶栏弹层共用这一份。
- 标签收藏不了：弹层里的标签行没有收藏图标，日志引用树里对标签按空格不响应。

## 最近与签出

- 「最近」只装签出成功的分支，失败的签出不留在列表里。上限 8 条，新的在前。
- 「签出标记或修订」这条动作不记进「最近」。它可能签出标签或任意修订号，记进去只会多一条永远不可点的记录。
- 远程分支行显示去掉远端名的短名，签出时也传短名：git 的 DWIM 只认短名，会自动建同名跟踪分支；
  传 `origin/x` 会直接游离到那个提交上。

## 整项隐藏与置灰

IDEA 的 `GitSingleRefAction.update` 写的是 `presentation.isEnabledAndVisible`，所以 `refClass` 不匹配、
`isEnabledForRef` 返回 false、`disabledForLocal` / `disabledForRemote` 命中，全都是整项消失。真正的置灰只有两处：
仓库还没有第一次提交，以及动作自己在 `updateIfEnabledAndVisible` 里写 `isEnabled = false`。逐条出处见
[`ref-action-matrix.md`](./ref-action-matrix.md)。

forge 照这条语义做。20 项的菜单里塞 8 项灰的，会把「类型上不适用」和「眼下缺前提」两类原因混在一起；不适用直接不出现，
剩下的置灰项才读得出是缺前提。

菜单按组拼接，只在非空组之间插分隔线。

当前落地的分档（`buildRefMenu`）：

| 引用 | 出现的项 |
| --- | --- |
| 本地分支（非当前） | 签出 / 从它新建分支 / 签出并变基到当前 / 检出并更新 / 与当前比较 / 显示与工作树的差异 / 将当前变基到它 / 将它合并进当前 / 新建工作树 / 推送… / 跟踪的分支子菜单 / 重命名… / 删除 |
| 当前分支 | 从它新建分支 / 显示与工作树的差异 / 新建工作树 / 更新 / 推送… / 跟踪的分支子菜单 / 重命名… |
| 远端分支 | 签出 / 从它新建分支 / 签出并变基到当前 / 与当前比较 / 显示与工作树的差异 / 将当前变基到它 / 将它合并进当前 / 新建工作树 / 用合并拉取到它（不可点）/ 用变基拉取到它（不可点）/ 删除 |
| 标签 | 签出 / 显示与工作树的差异 / 将它合并进当前 / 新建工作树 / 推送标签 / 删除 |

- 「更新」只出现在当前分支那一行（不在当前分支那行摆）。矩阵上 IDEA 是更新所选那条，forge 这条落的是 `git pull --ff-only`，动的始终是当前检出，摆在别的分支那一行等于挂错对象；缺口见 `../../plans/ref-actions-gap/`。
- 游离 HEAD 时「将当前变基到它」与「签出并变基到当前」置灰，提示「游离 HEAD 时没有可变的当前分支」：这时 `status.branch` 是 `HEAD`，不拦就会真去 `rebase HEAD`。`refAction` 那侧对这两个动作也各兜了一道。
- 当前分支一行没有签出与删除，两条都会动 HEAD：签出它自己没意义，删掉正站着的分支 git 也拒绝。IDEA 同样是整项隐藏
  （`GitCheckoutAction` 与 `GitDeleteRefAction` 都判当前引用）。重命名留着，`GitRenameBranchAction` 没有当前分支闸门，
  改的只是名字，当前检出不受影响。
- 远端分支没有推送：`GitPushBranchAction` 是 `disabledForRemote`，远端分支已经在服务器上，推送没有对象。
  同理没有重命名和更新，那两个是本地操作。
- 标签没有重命名：git 没有 `tag -m`，改名的唯一做法是新建一个再删旧的，那是两个动作。IDEA 的
  `GitRenameBranchAction` `refClass` 是 `GitBranch`，标签上整项不出现。标签也没有「从它新建分支」和「与当前比较」，
  同样是 `refClass` 闸门。
- 跟踪上游子菜单（「跟踪的分支 'origin/x'」）：有上游时出现，把同一套动作换成跟踪的那条远端分支再列一遍，
  并把子菜单自己的上游清空避免递归，照 IDEA 的 `GitTrackedBranchActionGroup`。
- 推送标签是单条动作，远端由 `push_target` 推出来：引用名前缀 → 该引用的上游 → 第一个远端。IDEA 那种
  「推送到 <每个远端>」的子菜单还没挂上，词典里的 `git.refPushTo` 没有被引用。
- 置灰只留给「有这一档动作、但眼下缺前提」的四类项：检出并更新与更新在没有上游时不可点，提示
  「该分支未跟踪上游分支」；这句说的是所选那条分支，不是手上这条，所以措辞里没有「当前」。远端分支上的用合并拉取到它
  与用变基拉取到它不可点，提示「要先切到那条分支才能拉取」。
- 菜单上画的键位（推送 `Ctrl+Shift+K`、重命名 `Alt+Shift+R`、删除 `Delete`）在日志的引用树里真绑，作用在点过或右键过
  的那条引用上。`Delete` 这一句两边都在抢：目录树那侧也绑了它，且只看自己有没有选中行、不看焦点落在哪。于是两边各让一道
  ——引用树这边只认焦点落在树里的那一下，接手后当场把事件吞掉；目录树那边焦点落在引用树里时整句让开。少了后一道，
  引用树里选中一条标签按 `Delete`，弹出来的是「永久删除文件」的确认框，删的是盘上的东西。

## 落到什么命令

一律是 Rust 侧以参数数组 spawn 系统 git，不经过 shell。

| 动作 | 命令 | 拼法依据 |
| --- | --- | --- |
| 签出 | `checkout <短名>` | 分支、标签、修订号都走这一条 |
| 检出并更新 | `checkout <短名>`，成功后再 `pull --ff-only` | 两步都成才走第二步 |
| 签出并变基 | `checkout <短名>`，成功后 `rebase <刚才那条分支>` | IDEA 那项是「切到这条，再把它变基到刚才那条上」 |
| 从它新建分支 | 弹窗起名 → `checkout -b <新名> <这条>` | 顺带切过去，照 IDEA 建完就在上面干活 |
| 将它合并进当前 | `merge --no-edit <引用>` | `--no-edit` 让 git 用自己的合并说明，不吃编辑器 |
| 将当前变基到它 | `rebase <引用>` | 撞冲突停在 `.git/rebase-merge`，由 `../git-commit/` 的横幅接住 |
| 更新 | `pull --ff-only` | 这条作用在当前分支上，不是所选那条 |
| 推送 / 推送标签 | `push <推出来的远端> <引用>` | 不碰当前分支的上游设置 |
| 重命名 | `branch -m <旧> <新>` | 弹窗预填旧名，整串选中 |
| 删除（本地分支） | `branch -d <名>` | 只用 `-d`：还没合并的分支 git 自己会拦，这里不替用户硬删 |
| 删除（标签） | `tag -d <名>` | |
| 删除（远端分支） | `push <远端> --delete <分支>` | 往服务器推一条删除引用，本地的远程跟踪引用跟着消失 |
| 新建工作树 | `worktree add <目录> <引用>`；填了新分支名则是 `worktree add -b <新分支> <目录> <引用>` | 弹窗默认落在仓库旁边：往仓库里塞一份工作树，git 会当成未跟踪内容。第二格是可选的新分支名——签的正是手上这条分支时，只有先开一条新分支才落得下去，留空才是直接签出所选那条 |
| 与当前比较 | 把日志中列筛成 `<当前>..<引用>` | 引用交给 `git log`，两段各自过校验 |
| 显示与工作树的差异 | 第三栏改成列 `<引用>` 对工作区（`diff --name-status -z`） | 弹层与日志树两处入口共用 `compareRef` 这一个状态 |

- 删除引用先过确认框，文案按类型换：本地分支和标签是「要删除「x」吗？此操作无法撤销」，远端那句写明后果
  「要从远端删除「x」吗？服务器上那条分支会一起没掉，此操作无法撤销」。确认按钮走 danger 配色。
- 名字两套校验。分支名和标签名只放字母数字与 `.` `_` `/` `-`，不许以 `-` 开头（会被当成选项）、不许含 `..`、
  不以 `/` 结尾。当版本引用用的那串另允许 `~` `^` `@`，不许含冒号。
- 「打开已有工作树」（`GitOpenExistingWorkingTreeForLocalBranchAction`）没摆：要先有 `git worktree list`
  才知道哪条分支检出在别处。
