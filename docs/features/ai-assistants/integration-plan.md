## 1. 目标与技术路线

在 Forge 现有 AI 助手侧栏和会话标签中完成真实对话：发送消息、流式回复、工具执行展示、权限确认、停止和恢复会话。

采用 **React 聊天界面 → Tauri Rust 后端 → 本机 CLI 子进程** 的结构：

- **Codex**：通过 `codex app-server` 的标准输入输出进行双向结构化通信。
- **Claude Code**：通过 CLI 的 `stream-json` 输入输出进行通信。
- Forge 负责界面、运行管理和记录；文件操作、模型调用和上下文管理由 CLI 执行。
- 不解析终端彩色文字，不另写模型调用循环，不额外引入 Node.js SDK 辅助进程。CLI 自身需要的运行依赖仍须满足。
- 第一版采用按回合启动、结束后清理的生命周期，通过原生会话 ID 续聊。后台任务等需要长驻进程的能力暂不承诺支持。

### 第一版范围

包含：文本对话、流式 Markdown、工具记录、授权与提问、停止、会话持久化和恢复。

暂不包含：图片、跨工具迁移上下文、自动导入全部 CLI 历史、多任务并发修改、插件市场、远程执行和电脑操作。

## 2. 启用与准备流程

1. 用户在设置中开启 AI 助手，总开关保持默认关闭。
2. 检测 CLI 安装路径、版本和所需运行环境。
3. 校验当前版本是否支持所需协议；安装成功不等于协议兼容或账号可用。
4. 第一版由用户在官方 CLI 中完成登录或供应商配置。Forge 不读取、复制或展示登录令牌，也不默认覆盖 CLI 全局配置。
5. 有可靠的官方状态接口时展示账号状态；没有时显示“尚未验证”，不能仅凭 CLI 已安装就显示“已登录”。
6. 新会话绑定明确的项目目录。第一版真实运行要求先打开项目，不把用户主目录隐式当成工作区。
7. 首次在项目启动前确认项目可信，说明 CLI 可能加载项目或用户配置中的指令、hooks、MCP 等内容。

### 账号与使用条款

本机 CLI 能否使用某种认证，与第三方产品是否获准提供该认证或订阅额度是两个问题。参考项目只能证明一种技术实现，不能证明已获得供应商授权。

发布前应核对官方条款，尤其是 Claude 的第三方登录、订阅额度和品牌使用限制。Forge 不自行实现非官方 OAuth，不提取订阅令牌作为 API Key，也不以更换接入方式绕过限制。

## 3. 一次对话的完整流程

### 3.1 创建与发送

1. 用户选择 Codex 或 Claude Code，新建 Forge 会话。
2. 会话先保存为本地草稿，第一次发送时才创建 CLI 原生会话。
3. 发送前确认：功能开启、CLI 可用、项目有效、无冲突运行。
4. 为本次发送生成独立的 `runId`，提前登记事件订阅和会话路由。
5. 后端再次校验开关、会话归属、工作目录、参数和并发限制，不能只信任前端按钮状态。
6. 保存用户消息和运行记录，启动对应 CLI，异步读取 stdout 与 stderr。
7. CLI 返回原生会话 ID 后，立即持久化与 Forge 会话的对应关系。

必须提前登记运行：CLI 的首条事件可能比发送命令的返回更早到达，否则会丢失内容或无法及时停止。

### 3.2 Codex 通信

推荐顺序：

1. 启动 `codex app-server`，使用 stdio，不开放网络监听端口。
2. 发送 `initialize`，确认响应后发送 `initialized`。
3. 新会话调用 `thread/start`；已有会话调用 `thread/resume`。
4. 设置明确的工作目录、沙箱与审批策略，不启用无约束执行。
5. 调用 `turn/start` 发送本轮消息，记录原生 thread ID 和 turn ID。
6. 接收文本增量、工具事件、文件变更和审批请求。
7. 以 `turn/completed` 的实际状态结束本轮；不能仅凭最后一段文字判断成功。
8. 完成落盘并清理本轮进程。

只使用经过验证的协议字段。实验性接口单独协商，不为了启用某个功能而默认打开全部实验能力。

### 3.3 Claude Code 通信

推荐使用的基础参数：

- `-p`
- `--input-format stream-json`
- `--output-format stream-json`
- `--verbose`
- `--include-partial-messages`
- 已有会话追加 `--resume <原生会话ID>`。

提示词作为结构化消息写入 stdin，不拼接到 shell 命令中。stdout 用于协议消息，stderr 用于诊断，两者不能混入同一聊天文本流。

参考项目使用 `--permission-prompt-tool stdio` 接收控制请求。Forge 应先验证支持版本和实际消息格式，再实现用户提问、工具审批及取消响应；不能将参考项目中的内部控制协议视为长期稳定契约。

需要区分文本增量、完整消息、工具调用和最终结果，避免同一段回复追加两次。最终结果和退出状态应共同用于判断是否完成；异常退出、没有结果或后台工作未结束都不能报告成功。

### 3.4 统一事件与展示

两个适配器将各自消息转换为 Forge 事件，前端不直接解析供应商协议。

事件建议包含：

- 身份：`sessionId`、`runId`、递增 `seq`。
- 内容：文本增量、完整消息、工具开始、工具输出、工具结束。
- 交互：授权请求、用户提问、请求失效。
- 状态：会话绑定、重试、用量、完成、中断和错误。

工具调用使用独立调用 ID 关联结果，不能仅按工具名称配对。终态应明确区分 `completed`、`cancelled` 和 `failed`。

后端对高频事件做有界批处理，前端合并更新。必须保留顺序、完整文本和中文/emoji 边界；后台标签仍接收事件，不依赖当前可见组件维持任务。

## 4. 权限、提问与文件修改

### 工具授权

1. CLI 发来需要人工批准的请求。
2. 后端保存原始请求上下文，向前端发送必要的展示信息和不透明请求 ID。
3. 前端展示拟执行命令、涉及路径或权限范围，提供“允许一次 / 拒绝”。
4. 后端校验请求仍属于当前运行且未被处理，再发送原生响应。
5. 用户停止、任务退出或请求被取消后，立即让对应卡片失效。

默认不提供“跳过所有权限”。没有可靠审批通道的操作应明确拒绝，不能为了让任务继续而自动放行。CLI 本身允许无需审批的操作，不伪装成全部经过 Forge 确认。

参考项目对 Claude 的 `AskUserQuestion` 提供界面，但对其他普通工具授权请求直接拒绝。Forge 必须补齐这部分，而不是原样照搬。

### 用户提问

用户提问与工具授权使用不同事件和界面。回答选项或文本不能被解释成执行命令的授权。提交答案同样校验运行与请求归属。

### 文件修改

- 展示 CLI 报告的文件变更，并接入已有差异查看、文件树和 Git 刷新。
- 区分“执行前的授权信息”与“执行后的修改结果”；事后差异不能冒充尚未执行的预览。
- 发送前检查项目中的未保存编辑：要求保存或暂停发送，避免 CLI 修改磁盘内容与编辑器缓冲区冲突。
- 同一会话使用 FIFO 队列，不同会话并行；队列项冻结发送时配置并可单独取消。
- 不自动回退整个工作区，不覆盖用户原有未提交修改。自动撤销需要独立的变更归属机制，暂不列入第一版。

## 5. 停止、关闭与异常恢复

### 用户点击停止

1. 将运行标记为正在停止，禁止继续提交本轮授权和回答。
2. Codex 优先使用 `turn/interrupt`；Claude 使用经验证的中断机制。
3. 等待有限时间，让适配器接收终态并保存部分输出。
4. 超时或协议失效时，终止整个子进程树并释放管道。
5. 将本轮保存为已中断；原生会话可恢复时，下一轮继续使用同一会话 ID。

Windows 进程树清理可以复用 Forge 现有 Job Object 的实现思路，但聊天任务需要独立的流式执行器，不能直接复用安装管理的有限尾部输出捕获逻辑。

### 标签与开关

- 切换标签：任务继续运行。
- 关闭正在运行的会话标签：明确询问“后台继续”或“停止并关闭”。
- 删除正在运行的会话：先停止并等待清理，再删除 Forge 记录。
- 关闭 AI 总开关：有运行任务时确认停止，清理后再关闭功能。
- 退出应用：停止所属任务并保存记录，不能留下无界面的孤立进程。

### 异常处理

明确区分未登录、额度限制、网络错误、CLI 崩溃、协议不兼容和本地持久化失败。

执行状态不确定时不自动重发用户消息，避免重复修改文件或执行命令。应用重启后，把上次未结束的运行标记为中断，允许用户查看部分结果并决定是否继续。

## 6. 会话保存与恢复

至少保存以下信息：

- Forge 会话 ID、工具类型、项目路径、标题与时间。
- CLI 原生会话 ID，以及可用的原生回合 ID。
- 本地运行 ID、状态、消息、工具记录和事件顺序。
- 用户选择的模型与权限设置，以及协议兼容所需版本信息。

采用后端管理的本地存储，第一版可以使用会话元数据文件与追加式 JSONL 事件记录；不要求立即引入数据库。存储需要格式版本、原子元数据更新、分页读取及损坏尾部恢复。

CLI 原生历史负责续聊所需上下文，Forge 记录负责界面恢复；保存展示文本不等于保存了原生上下文。原生会话不存在时明确提示，不静默创建新会话伪装续聊成功。

现有 localStorage 中的会话记录作为草稿迁移，只有首次真实运行成功取得原生 ID 后才绑定。迁移成功前保留旧数据，避免重复迁移和丢失记录。

默认只管理 Forge 创建或用户明确导入的会话。删除 Forge 记录不自动删除 CLI 原生历史，更不修改账号配置。

## 7. 推荐模块划分

### Rust 后端

- `src-tauri/src/ai_cli/`：保留现有安装、版本检测与更新管理。
- `src-tauri/src/ai_runtime/mod.rs`：对外命令、启用检查、会话与工作区校验。
- `src-tauri/src/ai_runtime/process.rs`：异步进程、双向管道、退出和进程树清理。
- `src-tauri/src/ai_runtime/registry.rs`：运行登记、并发限制、审批请求生命周期。
- `src-tauri/src/ai_runtime/events.rs`：统一事件结构及批量通知。
- `src-tauri/src/ai_runtime/codex.rs`：Codex app-server 适配。
- `src-tauri/src/ai_runtime/claude.rs`：Claude JSON 流与控制消息适配。
- `src-tauri/src/ai_runtime/store.rs`：本地会话、消息和恢复数据。

建议命令职责：发送、停止、回答问题、响应授权、读取会话消息、查询运行状态。前端不能提交任意可执行程序、shell 命令或原生 RPC 方法来替代这些受限接口。

### React 前端

- 保留 `AiSessionsPanel`、`AiProviderIcon` 和现有紧凑标题栏。
- 将 `AiSessionPane` 从占位页改成消息列表和输入区域。
- 独立管理运行状态与全局事件订阅，不让它们随会话组件卸载而消失。
- 消息、工具记录、授权卡和提问卡分开实现，不继续扩大 `App.tsx` 的职责。
- 保留现有主题、多语言和默认关闭的总开关。

## 8. 实施顺序与验收

### 当前实施进度

- 已实现：两家协议适配、受限后端命令、有界管道与进程清理、原生 ID 绑定和恢复请求、日志与分页、前端全局运行状态、聊天与交互卡片。
- 已实现：项目信任、未保存文档拦截、同会话 FIFO、关闭/删除/总开关清理、按项目过滤文件刷新。
- 已验证：模拟 CLI 的真实管道与审批标记文件、Unicode、续聊协议、中断、后代进程清理、超长/截断/异常输出、持久化恢复，以及前端事件和界面防护测试。
- 尚待人工验收：真实账号、额度与网络错误、供应商实际审批、重启后原生上下文续聊、Windows 桌面交互。不会为完成验收擅自调用模型或修改真实项目。
- 后续能力仍不包含：模型选择、附件、批量导入历史、长期后台任务。当前分页内存有界但仍扫描日志，尚未实现磁盘索引；前端按批增量投影，历史乱序合并时仍需要重放已加载事件。

以下四阶段是设计与验收顺序，不代表所有人工验收均已完成。

### 阶段一：协议验证

分别验证两家 CLI 的启动、发送、增量回复、原生 ID、恢复、中断和权限请求。先用模拟 CLI 测试；真实验证在用户批准的测试项目中进行，不默认消耗账号额度或修改当前项目。

产出：支持版本与能力清单、脱敏消息样本、明确的不支持项。

### 阶段二：基础聊天

完成公共运行管理，先接通 Codex，再使用同一套界面接入 Claude。支持发送、流式展示、停止、落盘与续聊。

验收：首条消息不丢失；中文和 emoji 不损坏；完成消息不重复；切换标签不断流；重启后能恢复记录并续聊。

### 阶段三：授权与编辑器联动

完成工具审批、用户提问、文件变更、未保存冲突检查及开关关闭清理。

验收：拒绝后不执行对应待授权操作；旧请求不能批准新任务；停止后没有遗留子进程；文件变更正确刷新；原有用户修改不被覆盖。

### 阶段四：稳定性与后续能力

验证启动失败、认证失效、断网、超时、崩溃、超大输出、事件重复、过晚事件、存储失败和版本变化。稳定后再加入模型选择、文件附件、选中代码提问与历史导入。

测试层次：协议解析单元测试 → 模拟 CLI 的真实管道测试 → 前端交互测试 → Windows 桌面端真实验证。模拟测试通过不能替代真实账号、权限和进程清理验证。
