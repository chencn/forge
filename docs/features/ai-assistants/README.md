# AI 编程助手：本机 CLI 聊天与安装管理

Forge 通过 Rust 子进程接入本机 Codex app-server 与 Claude Code JSON 流，提供聊天时间线、当前项目原生历史、模型与思考强度选择、上下文用量、审批、停止和原会话续聊。模型调用由官方 CLI 执行；Forge 不自行实现登录、不提取令牌，也不导入其他项目的会话。

聊天扩展流程、实现范围与限制见 [聊天体验与原生历史](chat-experience.md)。斜杠命令、参数语义及两家 CLI 的差异见 [斜杠命令协议](slash-command-protocol.md)。真实账号与 Windows 桌面完整验收尚未完成；不能将离线测试通过视作已完整还原官方行为。

当前属于首版实现，真实账号与桌面端完整验收尚未完成。适配版本、协议依据和验证边界见 [协议验证记录](protocol-validation.md)，设计流程见 [接入流程](integration-plan.md)。

## 入口与行为

- 功能默认关闭。设置 → 通用提供总开关，启用状态保存在全局设置中；只有开启后才显示「AI 助手 / 模型供应商 / Skills / MCP」设置菜单和活动栏入口。关闭时如有任务，先确认停止，等待清理成功后才关闭；保留已有会话和标签供再次开启时恢复。关闭后不自动检测或加载会话。安装管理执行期间暂时禁用开关。
- 设置 → AI 编程助手：开启后检测本机安装、版本、可执行路径、安装来源和最新稳定版本；执行安装、更新、卸载。标题行只保留重新检测按钮。
- 右侧活动栏 → AI 编程助手：开启后默认位于顶部第一项；当前工作区的全部本地会话统一显示，不按工具分组。侧栏列表采用章节化布局（对照 codeg 侧栏）：固定的「新建会话 / 搜索」两行不随列表滚动，其下依次是「置顶」「会话」「最近」三个可折叠章节；forge 只支持单个项目，没有参考实现里的项目（文件夹）分组、worktree 与标签体系。
- 会话卡片保留竖向导轨线与工具图标，不再叠加状态圆点；行尾相对时间（now/5m/3h/2d…）按章节与排序模式取创建时间或最近活动；悬停时时间换成「置顶 / 归档」快捷按钮，停住 0.5 秒在行右侧浮出只读详情气泡（标题、工具、项目路径、创建/最近活动时间与会话 ID），右键菜单提供新建、重命名、置顶、归档与删除。
- 侧栏标题行是「定位当前会话、展开/收起全部章节、视图选项」三颗按钮；排序方式（创建时间/最近活动）、章节顺序、显示「最近」与显示已归档放在视图选项菜单里，重新检测与设置入口也在其中。视图偏好存在 WebView 本地存储，「最近」的展开页数只在本会话内有效。
- 「最近」章节默认收起并贴在侧栏底部，点击后回到「会话」章节下方并向下展开；内容按最近活动倒序、默认一页 10 条，可用 ⋯ 菜单按全部/Claude/Codex 筛选；行尾「还有 N 条」逐页展开，展开超过一页后悬停出现「只显示前 10 条」的收起入口，会话删到一页以内时收起入口自动消失。
- 新建会话先打开草稿标签与欢迎页（渐变标题、工具胶囊选择器、输入框与底部小提示，工具按工作区记忆），首条消息发出时才真正创建会话并自动把它发出，标题也从那句话自动取（没发过消息的会话显示「未命名会话」）；未安装任何工具时欢迎页给出设置入口。安装状态在桌面进程内检测一次，切换项目、侧栏刷新或 WebView 刷新均复用，直到退出应用；Forge 安装/更新/卸载后失效重查，独立的联网更新查询不阻塞使用。
- 未安装工具时提供前往设置的入口；检测失败与未安装分别提示。联网版本查询失败不影响已确认安装的工具。工具卸载后保留已有本地会话，只从新建选项中移除。
- 工具选择、会话列表、编辑器标签、会话页和安装卡片统一使用 Claude / Codex 品牌图标：Claude 使用品牌橙色，Codex 使用浅色主题黑色、深色主题白色的单色图标。图标本地打包，MIT 许可与来源见 `public/licenses/lobe-icons.txt`。
- 会话标签重复打开复用同一标签；支持重命名、删除、关闭标签、关闭其他/全部标签；置顶与归档状态持久化在会话元数据中（`pinned`/`pinnedAt`/`lastActivity`）。
- 关闭运行中的标签时可取消、后台继续或停止并关闭；切换标签不中断任务。删除会话需要确认，并先停止运行再删除 Forge 记录，不删除 CLI 原生历史。
- 标签、输入框草稿（按会话）与发送历史（按工程，供 ↑↓ 召回）都保存在 WebView 本地存储，按工作区隔离；真实聊天元数据和事件由 Rust 持久化，重新开启项目时补回会话。
- 聊天要求先打开有效项目，并确认项目及其 CLI 配置可信。存在未保存项目文档时暂停发送；同一会话按 FIFO 串行，不同会话可并行，运行期间仍可继续提交和取消排队任务。
- 停止、全部停止、关闭项目都先在锁内决定「停哪一个」，再到锁外等待清理，一条卡死的 CLI 不会按住其他会话的发送与队列调度；关闭一律先清空队列，收尾不会把用户刚停止的任务又调度起来。排队顺序由后端事件流统一写出，多个窗口得到同一顺序。
- 输入框对照 codeg 重排为单层圆角卡片：附件缩略图条在上、编辑区居中、底部动作行（左侧「+」附加/斜杠菜单与「模型/强度/权限」设置芯片，右侧 32px 圆形发送/停止按钮），聚焦时整盒 3px 内描边；模型选择收进设置芯片点开的可搜索列表（分组、勾选、等宽 ID 提示、默认徽标），弹层里只有选择与强度/权限开关——不提供添加模型、也不提供手动刷新入口；增删自定义模型在设置页的「自定义模型」区；强度与权限为分段控件，Codex 的 Fast 开关为开关行，底部只留目录来源一行小字——重置与 CLI 管理都在设置页，不在弹层里；上下文芯片与压缩建议位于盒下状态行右侧。工具胶囊选择器（欢迎页）滑块随选中项滑动、未选中项收成图标，持续重测过渡中的胶囊尺寸。
- 会话页顶部为透明横幅（40px、下沿半透边）：工具图标 + 项目名面包屑 › 会话标题（运行/排队/冲突时附状态字），右侧 ⋯ 菜单提供新建、重命名、置顶、归档、设置与删除；正文区右缘有消息导航芯片，展开按序号列出**整个会话**的每一轮用户消息（首行摘要 + 本轮改动文件数）：索引不在正文那一页事件里挑，而是第一次点开时才从事件日志尾部扫出来，列表往上滚一档加一档；点还没加载进正文的那一轮，先按序号把中间的事件连续补齐再滚动定位并闪烁高亮。
- 会话时间线对照 codeg：用户消息为右对齐圆角气泡（悬停复制、超长折叠渐隐、图片缩略图贴右上），回复正文无气泡；连续工具过程折成带活动微光与点线引尾的折叠头，工具行挂左侧活动导轨与状态环（运行虚线旋转、失败红、完成实线环），明细收进圆角卡；思考行带首行摘要标题；代码块为整卡 + 40px 哑色题头（语言居左、复制居右、正文限高滚动）；子代理渲染为委派卡片并可打开独立会话，Claude 从 sidechain 日志导入完整对话，Codex 运行中显示父连接的活动摘要并在终态后从独立 rollout 回填标题与完整历史；压缩事件为居中渐隐分隔线。
- 会话页支持流式 Markdown（代码高亮 + 逐块复制）、公开推理摘要、工具命令/补丁/结果、原位审批与提问、上下文详情、停止和历史分页。打开会话取的是**最新**一页并直接停在底部，往上翻才逐页取更早的记录；连续的读取/搜索/命令条目折叠成一组，展开状态跟着条目走；一屏最多铺 120 条，窗口里还藏着的先放出来、放完了才向后端要更早的一页，翻页期间视线钉在原来那条消息上。脱离底部时钉住当前位置并数新增条数，「回到底部」按钮带着未读数字；回合失败在原位给出一行未加盒的错误说明（圆圈叹号 + 灰字，与参考一致，无重试按钮——重试即重发）；运行中在时间线末尾以图标脉动加状态字标示。审批卡片按后端能力给出「始终允许」「按目录允许」「编辑后再允许」。待答复的审批卡、没有归属的错误、正在跑的这一轮与排队项都钉在输入框上方，本轮改过的文件汇总收在底栏，对话列里只有对话。上下文接近窗口时给压缩建议，压缩区只在有建议、正在压缩或用户开过自动时出现在 token 芯片点开的用量卡里（标题 + 进度条 + 已用/上限 + token 明细行，构成明细收在同卡滚动区），达到阈值且用户打开自动那档才动手；这一轮跑的就是压缩时，芯片、标题状态和进度条一起说明「正在压缩上下文」。输入框支持粘贴、文件选择器和拖拽三条附件入口：按文件头认 PNG/JPEG/GIF/WebP，单张与张数上限由后端一次性报给前端（当前 8 MiB / 每条消息 8 张），落进应用缓存沙箱后 Claude 走内联 base64、Codex 走原生 `localImage` 路径，链接与沙箱外路径一律拒绝；未发送的附件在点「移除」时立即删盘，已发送的随会话删除，缓存里超过 30 天的无主生成文件在进程首次授权时回收。模型与强度真实传给 CLI；Claude 模型为官方别名/自定义 ID，Codex 可读取动态模型与档位。Markdown 清理危险标签，正文不自动加载外部图片（附件用自己的 asset 回显）。回复里的本地文件位置可以直接点开跳到编辑器：markdown 链接写成 `src/a.ts:12`、`./a.md#L9`、`C:\repo\a.ts` 或 `file:///…` 都认，相对路径按工程根还原；工具摘要、明细里的动作行与补丁头、底栏「本轮改过的文件」列表同样可点，行号只取 CLI 报的 `startLine` 与补丁头 `+N`，取不到就跳到文件开头。
- 账号状态显示尚未验证。请先在官方 CLI 中登录；Forge 不按 CLI 版本号拦截启动，任何已安装版本都会启动，能力差异由运行时探测与如实报错处理。
- 文件事件按所属项目触发文件树、Git 和已打开文档刷新。关闭项目会先停止其 AI 任务；目录被移除时仍能执行清理。
- 运行中重命名会话目前会被后端会话锁拒绝，请等待本轮结束后操作。
- 简体中文、繁体中文、英文均提供文案，颜色使用现有工作台主题变量。

## 计划审阅、后台任务与会话级授权（本轮增量）

- 计划模式：输入框设置芯片新增「计划模式」。Codex 通过 `collaborationMode`（实验能力，只在计划/决策回合开启）进行规划，完成的 `plan` item 成为可审阅卡片；Claude 以 `--permission-mode plan` 加只读工具白名单运行，不产生类型化审阅记录，计划正文按普通回复展示。
- Codex 计划审阅：审核卡固定在输入框上方，支持批准执行、要求修改（必填反馈）与暂不执行。批准/修改走会话目录下 `plans.json` 的版本与 CAS；决策回合启动前用 `thread/turns/list` 重新核对计划 id 与正文指纹，正文变化即过期，绝不执行已变化的计划。批准 ≠ 执行成功，执行状态单独记录。双击或两个窗口只有一个提交者。
- Claude 后台任务：`background_tasks_changed` 与 `task_notification` 进入事件流；仍有后台任务时回合结束不杀进程，界面显示后台任务条。任务结束后 CLI 自己退出或补发后续回合；用户在此窗口发的新消息仍排在同一会话队列里，等这一轮收尾后按 `--resume` 启动，而不是写进正在驻留的进程。
- 权限拒绝与额外目录：headless 下被权限系统拒绝的工具结果会变成可行动提示；确认后把真实目录记入本会话的附加目录，下一轮 Claude 以 `--add-dir` 生效，Codex 以 `turn/start` 的沙箱策略 `writableRoots` 生效，并与项目里已配的可写根目录、网络开关合并而不是替换。Codex 当前是只读沙箱时收不下这些目录，会在时间线里说明原因，不静默丢弃；完全访问本就覆盖这些目录。Codex 主动申请扩大权限时不再静默拒绝：进审批卡，批准等于原样授予它申请的那份，且没有工具名就没有「本轮不再询问」——Forge 不替 CLI 记住越权。
- MCP 快照：会话底部列出本次实际加载的 MCP 服务与状态——Claude 取 `system/init` 报告的那份，Codex 在回合起来后问 `mcpServerStatus/list` 拿全表、再由启动状态通知逐台改写后整表重发；探测失败或报空时整块不出现，不摆空表。只读展示，Forge 不向会话注入任意 MCP 命令。
- MCP 管理与市场：本地页读写 Claude `~/.claude.json` 与 Codex `config.toml` 的原生条目；市场支持官方 MCP registry 与 Smithery，列表固定 `version=latest` 并按完整服务器名去重。详情从 registry 读取全部安装方式（npm、pypi、包内远程、独立远程、Smithery 连接），展示协议、版本、验证、部署与使用量；安装参数按 env / header / query / argv 的位置写入，必填缺失拒绝安装，Codex 不提供 SSE。安装后使用 registry 的完整名称作为本地配置键，配置 JSON 可在安装前编辑。
- Codex 异步提问：AgentMessage 上的问题转成提问卡，回答通过 `turn/steer` 写入当前回合，不复用普通授权回包。
- 以上能力均只接受受限的结构化参数；计划审批 id、版本、决策与反馈由前端提交，执行指令、原生计划和路径解析全部留在后端。

## 安装策略

### Claude Code

- 从官方 npm 的 `https://registry.npmjs.org/@anthropic-ai/claude-code/stable` 查询稳定版本，校验包名和正式版本号，按精确版本执行 `npm install --global @anthropic-ai/claude-code@<version>`；更新使用同一方式，卸载使用 `npm uninstall --global @anthropic-ai/claude-code`。
- 固定官方 npm registry，启用平台可选依赖，不再下载或执行 `claude.ai/install.ps1` / `install.sh`，因此不再经过此前触发 `System.Xml.XmlDocument` 的安装路径。
- 当前 stable 包要求 Node.js 22+；缺少 Node.js / npm 或版本不足时显示原因，不代为安装环境。
- 来源识别校验 npm 全局 prefix/root、包名、bin 声明和启动器目标，兼容旧版 `cli.js` 与新版 `bin/claude` / `bin/claude.exe` 入口。
- 已有官方原生安装仍检测和显示，但只读，不自动迁移、更新或卸载。未知来源、多份安装及残留文件继续保守拦截。
- 卸载只通过 npm 移除程序包，不主动删除 `~/.claude`、`~/.claude.json` 或会话历史。

### Codex

- 从 `https://registry.npmjs.org/@openai/codex/latest` 查询正式版本，校验包名和三段纯数字版本，拒绝预发布版本。
- 使用当前可用 npm 的全局安装目录，按查询到的精确正式版本安装；固定官方 npm registry，启用平台可选依赖。
- 管理已有 npm 安装前核验全局 prefix/root、包名、bin 声明及启动器目标，防止卸载到另一份安装。
- Node.js / npm 缺失时展示原因，不代为安装 Node.js，不自动提权。

### 保守处理

- 其他安装渠道、未知包装器、多目录重复安装、残留文件或无法确认来源的安装只展示信息，不自动接管。
- 更新仅接受比当前版本更高的稳定版本，不自动降级。
- 官方版本查询失败（包括超时、HTTP 错误或无效响应）后，自动尝试国内 `npmmirror`：Codex 使用 `https://registry.npmmirror.com/@openai/codex/latest`；Claude 使用 `https://registry.npmmirror.com/@anthropic-ai/claude-code/stable`，保持 stable 通道，不以 latest 替代。
- 镜像响应仍校验包名和正式版本号。仅使用版本元数据，不使用镜像返回的 tarball 或脚本地址；安装/更新来源保持官方不变。界面标明镜像来源及同步延迟风险；两个来源都失败时保留两次错误。
- 网络失败不抹掉本地检测结果；允许管理的卸载不依赖版本查询成功。
- 命令退出成功后还需验证实际安装结果，避免把安装脚本的静默失败当作成功。
- `--version` 与 npm 目录查询有 20 秒超时；网络请求有 25 秒超时；安装命令最多执行 15 分钟。输出保留每路最后 32 KiB。
- Windows 使用 Job Object，Unix 使用独立进程组，结束或超时清理子进程树。Windows 命令不弹出控制台。
- 前后端均互斥。前端状态独立于设置组件，切换标签不丢失运行状态；后端重新校验权限，拒绝任意 provider/action 或命令文本。
