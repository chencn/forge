# 提交面板

活动栏"提交"打开的左侧工具窗口，上方变更树，下方说明框和提交按钮。对应 IDEA 的 Commit 工具窗口。

## 分组

从上到下：未合并、已暂存、未暂存、未进行版本控制、已忽略。勾选修正时在最后追加"上次提交"一节。空组不画。

- 未合并只在有冲突时出现，冲突文件只出现在这一组，`isIndexChange` 和 `isWorktreeChange` 都排除 `conflicted`。同一文件同时出现在已暂存和未暂存会被读成两份状态。
- 未进行版本控制来自 porcelain 的 `??`。
- 已忽略来自 `status --porcelain --ignored=matching` 的 `!! ` 行，只在视图选项打开时取。这些行没有差异可看，点开是文件本身，字色退到 `--text-muted`。关掉开关时清单立即清空，不留旧数据。右键两项：从忽略列表移除与复制路径。移除走的是 `check-ignore -v` 反查出来的**那一条规则**，删的是它所在那一行——`logs/run.log` 是被 `*.log` 盖住的，照路径写一条反向规则动不到它；规则落在 `.git/info/exclude` 时也照样删那一行，落在仓库外（全局忽略文件）时只报在哪个文件，不动它。
- 组标题右侧显示本组文件数，字色 `--text-tertiary`。未合并组的标题行最右有一个"解决"链接。

## 树的形状

- 选"按模块分组"时每组外面套一层仓库根节点，显示目录名，绝对路径在悬停提示里。根节点 key 用 `${prefix}⌂module`，目录 key 不含 `#` 和 `⌂`，两套 key 加组前缀不会撞。
- 只有组标题是 600 字重，仓库根、目录、文件都是普通字重。仓库根的名字用 `--text-primary`，比普通目录行亮一档，对应 IDEA 的项目节点。组之间不画分隔线，靠标题行 `padding: 11px 10px 4px` 的留白。
- 组标题文字前留 28px（`HEAD_TEXT`）放箭头，组内每行都从这一列起，行上的箭头不会和组标题的箭头并排。文件行没有箭头，从 34px（`HEAD_MARK`）起，多出的 6px 让状态字母顶在箭头那一列。每深一层目录加 13px。
- 目录默认收起（`openDirs` 初值为空），组标题默认全展开。IDEA 那棵树先给人看总量，点开哪组记哪组。日志窗口第三栏相反，那边一次只看一次提交。
- 状态标记是索引位和工作区位两个字母并排，空位用 `·` 占住，等宽 22px。已暂存组的徽标转绿。

## 暂存和图标条

- 行末的就地暂存图标方向跟组走：未暂存组是加号，已暂存组是减号。目录行上的图标作用于整棵子树。平时 `opacity: 0`，鼠标进入该行或键盘 focus 时显示。冲突行不显示这个图标，带冲突标记进索引等于把冲突藏起来。
- 树上方六个按钮：刷新（loading 时转）、暂存所有已跟踪的改动、全部取消暂存、折叠全部、展开全部、视图选项。第二个只暂存 `trackedChanges`，未跟踪的留给单独动作，对应 IDEA 的 Stage All Tracked。
- 折叠全部清空 `openDirs` 并把 `c|s|w|u|ig` 五组的标题收起；展开全部把未合并、已暂存、未暂存、未跟踪四组的目录 key
  和模块 key 塞进 `openDirs`，同时清掉折叠的标题。两边都算上未合并那一组：撞冲突时按一次展开全部要能直接看到要解决
  的那几个文件，只展开三组会把它们留在收起的模块行底下。修正组的标题不在这两个动作的名单里，那一节是平铺文件列表。
- 视图选项三项：分组依据 目录 `Ctrl+Alt+P`、分组依据 模块 `Ctrl+Alt+M`、显示忽略的文件。前两个键只在提交窗口可见且日志窗口关闭时生效，日志窗口一开这两个键归日志第三栏。两处都在做分组依据，同一时刻只能有一套语义。

## 说明框和提交

- 头部一行控件：修正勾选、上次提交下拉、说明历史、右侧文件数统计。统计数的是按下提交会带走多少文件，按已暂存项的索引位分 已添加(A)、已删除(D)、其余算已修改。宽度不够时退成 `+N *N -N` 的紧凑写法，靠 `ResizeObserver` 量图例的自然宽度。暂存区为空时整条不画，包括"提交全部"实际会带走全部已跟踪改动的情况。
- 勾选修正时取 `git_commit_detail`，把那条提交的 `subject`、空行、`body` 填进说明框，取消勾选还原成先前写的（`messageBeforeAmend`）。变更树最底追加一节，标题是那条提交的说明，列它改到的文件，点开看的是那次提交里的差异而不是工作区比对。提交按钮改字成"修正 (I)"。落 `commit --amend -m <说明>`，说明为空时落 `--amend --no-edit`。带 `-m` 是因为少了它 git 会把说明当 pathspec，报 "did not match any file(s)"。
- 上次提交下拉列 HEAD 加还没推出去的那几条（`log -n20 HEAD --not --remotes`，遇到第一个合并提交截断）。除第一条外全部不可点，提示修正这条要改写它之后的历史。
- 两个按钮：提交 (I)、提交并推送(P)...。提交可用的三个条件：有说明或勾了修正、有暂存（或提交全部、或修正）、没有未合并文件。最后一条的提示照 IDEA 的"先解决冲突才能提交"。暂存区空着时另有一句"请先暂存改动再提交"，但开着"提交全部"且确有已跟踪改动可带走时这句不画——按钮是可点的，留这句话自相矛盾。`Ctrl+Enter` 提交。提交并推送是提交成功后调 `git_push(false)`。
- "没有暂存文件时提交全部"是设置项 `commitAllWhenNothingStaged`，默认开。暂存区为空但有已跟踪改动时，提交前先把那批全部 `add` 上。先替人暂存是因为后端提交的是索引，中途失败会留在索引里，可以用"全部取消暂存"退回去。
- 单击行开比对，已暂存那侧比 HEAD 到索引，未暂存那侧比索引到工作区。重命名的基线取旧路径，否则整份文件会显示成新增。双击行为看设置项"双击时打开"。

## 变更行右键

照 IDEA 的 `Git.Stage.Tree.Menu` 分组。冲突行先来一组：解决冲突、采用对方改动、采用本地改动。然后 暂存或取消暂存、搁置、回滚、从版本控制移除、忽略文件。再一组 显示差异、在独立窗口显示差异、三向比对、编辑源、创建补丁、创建补丁到剪贴板、复制路径。最后 历史记录。

- 回滚只给未暂存的已跟踪文件，落 `restore --worktree -- <路径>`（revision 留空即从暂存区索引恢复）：只丢未暂存那层，已暂存的内容原样留在索引里；文件没有暂存内容时索引就是 HEAD，等价于回到上次提交。不碰索引。
- 忽略文件是往 `.gitignore` 末尾追加一行，已写过的不重复，仓库里没有该文件就从空写起。
- 历史记录把日志中列筛到这一条路径并打开日志窗口。
- 创建补丁取 HEAD 到工作区那一段。默认名的主名走 `patchStem`：`.gitignore` 这类只有扩展名写法、没有主名的名字整个退回，不然会拼成「-worktree.patch」。两侧内容没差异时（未跟踪文件相对 HEAD 就是这样）不写文件，改报一句「未写出补丁」——落一份 0 字节补丁过去会被读成补丁做好了。
- 目录行的菜单只有两条：暂存整个目录、复制路径。
- 模块行（仓库根那一行）右键给两条：按这一组的状态写 暂存 或 取消暂存，作用范围是这一组里该仓库的全部变更；
  另一条是复制路径，复制的是仓库根。修正那一节的模块行只给复制路径，那一节列的是上次提交改到的文件，
  动不了索引。
- 空白处（落点不在任何一行上）右键给整树五件事：暂存所有已跟踪的改动、全部取消暂存、折叠全部、展开全部、刷新。
  这五条和图标条上那五颗是同一批函数，禁用条件也只写一处。这里不摆「新建文件」那一类，那属于资源管理器。
  判据用 `closest('.change-row')`：组标题行、说明段落都算空白，只有具体某一行才走它自己的菜单。
- 五项摆着但不可点：不带内容暂存、搁置、从版本控制移除、在独立窗口显示差异、三向比对。保留不可点项是因为 IDEA 那份菜单的分组形状是判据，抹掉一半会让人以为这里另想了一套分组。缺口见 `../../plans/change-selection-actions/`。

## 停在动作中间

`git_probe` 探四个落点：`.git/MERGE_HEAD`、`.git/rebase-merge` 或 `rebase-apply`、`.git/CHERRY_PICK_HEAD`、`.git/REVERT_HEAD`。`recoveryOf` 按 变基 > 合并 > 优选 > 还原 取第一个，一次只认一个，真要嵌套 git 在起手时就会拦。

- 说明框上方（图标条下面）出一条横幅，给继续和中止。顶栏分支控件右边那对按钮读同一份 `recovery`，继续绿、中止红，侧栏收起时它们不跟着收。两处派到同一对命令，文案在 `src/lib/recovery.ts` 一份走到底，避免两边对不上。
- 继续对合并、优选、还原是落一次提交，对变基是接着往下跑。四条 `--continue` 都带 `-c core.editor=true`，否则编辑器弹在 webview 外面，命令一直不返回。中止那四条直接 `--abort`，仓库退回动作之前。
- "解决冲突"（组标题后的链接、冲突行菜单项、说明框上方提示，都开同一个弹层）逐个冲突文件按一边了结：`checkout --ours` 或 `--theirs` 之后紧跟 `add`，让它从未合并组消失。冲突全清完弹层自动关闭。删除和修改这类冲突有一边不存在，`checkout` 会失败，git 的原文报回界面。

## 面板头部的齿轮

对应 IDEA 的 `CommitView.GearActions`，两项：双击时打开（差异 / 源文件）、没有暂存文件时提交全部，存在 `settings.commit`。视图选项那三项（目录、模块、忽略的文件）不落盘，是窗口的内存状态。
